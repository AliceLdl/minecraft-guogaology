# WORK-0506 · 26.3 数据格式修复（首次让 26.3 目标能真正进世界）

## 现象（用户实测）
新建 26.3 世界卡在「正在准备生成世界」。日志：

```
IllegalStateException: Unknown registry key in
ResourceKey[minecraft:root / minecraft:loot_condition_type]: minecraft:block_state_property
...
java.lang.IllegalStateException: Failed to load registries due to errors
>> Errors in element guogaology:recipes/chair: No key recipes in MapLike[{"recipe":"guogaology:chair"}]
```

⇒ **注册表加载阶段**就有 22 个元素解析失败，世界生成还没开始。

## 根因（两处 26.3 数据格式漂移，均为移植遗留，与 0.5.4/0.5.5 新内容无关）
| # | 旧格式 | 26.3 新格式（原版样例为准） |
|---|---|---|
| 1 | 掉落条件 `minecraft:block_state_property` + `block` + `properties` | `minecraft:match_block` + `blocks` + `state`<br/>样例 `data/minecraft/loot_table/blocks/acacia_slab.json` |
| 2 | advancement `minecraft:recipe_unlocked` 判据用 `recipe` | 用 `recipes`<br/>样例 `data/minecraft/advancement/recipes/brewing/blaze_powder.json`（主机侧既有转换已用列表形式，实机通过） |

**为什么之前的转换没生效**：`tools/prepare_port_resources.py` 里的 `convert_263_misc()`（含 recipe 改名）
跑在 `prepare_outer_resources.prepare()` **之前**，而外域内容导入会**再写一遍** `advancement` /
`loot_table`，那批文件因此绕过了 26.3 转换。

## 改动
- `tools/prepare_port_resources.py`：新增 `convert_263_data_fixups(out)`（**幂等**，递归处理
  嵌套 `all_of/terms` 等形状），并在 `prepare_outer()` **之后**调用（仅 26.3）。
  未命中这两处的文件原样写回。
- `gradle.properties`：mod_version 0.5.5 → 0.5.6。

## 验证
- `prepare_port_resources.py 26.3 0.5.6`：报告 `2 loot conditions renamed`；
  全量扫描生成资源：旧掉落条件残留 **0**、旧 `recipe` 键残留 **0**。
- 构建 jar 内同两项复扫：残留 **0**；`climbable` 标签与 `SurfaceShaftField` 均在。
- 三审计（audit_resources / audit_localization / audit_outer_content）全绿。
- **未验证**：实机进世界（需用户复测）；1.21.x / 26.2 目标构建（沙箱 loom 限制，且本次只改
  26.3 专属分支，不影响其它目标）。
