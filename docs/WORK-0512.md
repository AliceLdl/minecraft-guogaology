# WORK-0512 · 软糖罐贴图修复（UV 越界）+ 紫菜桌上所有果糕都换成软糖罐

用户反馈两条（原话）：

1. **软糖罐在游戏里显示为紫黑缺少贴图。**
2. **紫菜桌上所有果糕都要以软糖罐代替。**

## 一、紫黑的真因：模型 UV 用了「贴图像素」而不是「0~16 单位」

MC 的模型 UV **永远是 0~16 单位空间**，与实际贴图分辨率无关（16×16 贴图 = 整图；32×32 / 128×128 贴图同样用 0~16 表示整图）。
我第一版把 32×32 图集的**像素坐标**直接写进了 `uv`（最大到 32）⇒ 采样落到 sprite 之外（图集里没有图的地方）
⇒ 游戏里就是**紫黑缺失贴图**。贴图文件本身没问题（PNG 有效、字节与源文件一致、jar 内也在）。

**证据（不是凭记忆）**：全仓 391 个「显式 UV + 贴图 >16px」的模型，UV 上限**全部 ≤16**
（例如 128×128 的彩灯 `cyan_guogao_lantern_part_*.json` 也是 16；32×32 的 `amber_guogao.json` 是 14）。
只有我新写的 `gummy_jar.json` 是 32 ⇒ 唯一越界者。

**修法**：按 `scratch/make_gummy_jar_art.py` 里声明的图集分面，把像素坐标**除以 2** 换算成 16 单位：

| 分面（像素） | 用途 | 模型 UV（16 单位） |
|---|---|---|
| A `(0,0)-(14,12)` | 罐身四面 | `[0,0,7,6]` |
| B `(14,0)-(26,2)` | 罐肩 | `[7,0,13,1]` |
| C `(14,2)-(22,4)` | 罐颈（金属盖裙） | `[7,1,11,2]` |
| D `(22,0)-(30,8)` | 瓶盖顶面 | `[11,0,15,4]` |
| E `(0,12)-(14,26)` | 罐身顶面（俯视） | `[0,6,7,13]` |
| F `(14,8)-(28,22)` | 罐底 | `[7,4,14,11]` |

面分配：罐身四侧 = A、罐身上面 = E、罐身下面 = F；罐肩四侧/上面 = B、下面 = F（被罐身挡住）；
罐颈四侧 = C、罐颈上面 = D（俯视金属盖）、罐颈下面 = C。**贴图一个字没改**（美术是用户逐轮定的），只改 UV。
构建产物实测：**jar 内模型最大 UV = 15** ✔

## 二、防回归：`audit_resources.py` 新增 UV 范围检查

新增字段 `out_of_range_uv`：遍历所有 `models/**` 的模型 JSON，任何 `uv` 值 <0 或 >16 就报错退出（`--check` 也会红）。
`core_meshes/**` 是本模组自己的网格格式（不是原版模型）⇒ **明确排除**在该规则之外。

- 正向：`out_of_range_uv = []` ✔
- **阴性对照**：临时把 `gummy_jar` 的 `uv` 改成 `[0,0,32,32]` ⇒ 审计**正确报错** ✔，随后原样恢复 ✔

## 三、紫菜桌：所有果糕都换成软糖罐

`LaverTableFeature.tableGummy` 原来保留 1/5 概率放花面果糕（`if(random.nextInt(5)==0)return embossed;`），
现按用户要求**删掉该分支**：能拿到 `guogaology:gummy_jar` 就一律放软糖罐，只有方块未注册时才退回花面果糕。
改了两份（`ports/common/.../LaverTableFeature.java`、`ports/26.3/src/main/java/.../LaverTableFeature.java`），
`placeGummies` 的调用点与签名不动（1.21.1 旧版桥接依赖这个签名）。

**产物核验**：`javap -c` 反编译 jar 里的 `LaverTableFeature.tableGummy` —— 只剩
「取 `gummy_jar` → 是 AIR 就用传入的果糕 → 否则用软糖罐」，**没有任何 `nextInt` 调用** ✔
