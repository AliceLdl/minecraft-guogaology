# WORK-0518 · 软糖罐生成规则（每块桌板 1% 独立概率）+ 盖子去点 + 果糕配方用果糕凝胶

版本号按用户要求**继续维持 0.5.4.0**（不递增）。

## 一、生成规则（用户原话）

> 「每个紫菜桌上的每个紫菜桌板上方都有 1% 的独立概率生成，若与羊毛同时生成则软糖罐优先」

- 旧规则：`gummyCount(random)` 用几何分布（`while nextInt(5)==0`）抽一个数量，再从桌板里随机取那么多个位置放软糖罐。
- 新规则：**遍历每一块桌板**（`tableSurface` 返回的每一个位置），**各自独立** `random.nextFloat() < 0.01f` ⇒ 每块桌板 1%。
- **软糖罐优先于羊毛**：`applyDecor` 里顺序是 `placeWool(...)` → `placeGummies(...)`，
  后者直接 `setBlock` 覆盖 ⇒ 同一格上羊毛被软糖罐顶掉 ✔（不需要额外判定）。
- 新增常量 `public static final float GUMMY_JAR_CHANCE = 0.01f;`，两份实现
  （`ports/common/...`、`ports/26.3/src/main/java/...`）都改了。
- `gummyCount(...)` 保留但已不再被调用（避免动其它引用）。

**产物核验**：`javap -c` 反编译 jar 里的 `placeGummies` ⇒ `RandomSource.nextFloat()`（偏移 37）
→ `ldc_w float 0.01f`（42）→ `setBlock`（71）✔ 与源码一致。

## 二、盖子中间那个不对称的点（用户原话）

> 「软糖罐的盖子上中间有一个不对称的点，改成对称的」→「把这个点去掉就好了」

- 真因：盖顶 8×8 贴图里在 `(左上+3, 左上+3)` 单独点了一个 `METAL` 暗像素（高光块里的一个点），偏左上 ⇒ 看着不对称。
- 已**删掉该像素**。现在盖顶是严格对称的三层：外圈 `#484e60` / 中圈 `#bcc0cd` / 中心 4×4 `#e6e9f4` ✔

## 三、果糕配方：粘液球 → 果糕凝胶（用户原话）

> 「把合成果糕所需要的粘液球都改成果糕凝胶」

- 8 个文件、每文件恰好 1 处 `minecraft:slime_ball` → `guogaology:fruit_cake_gel`：
  - `data/guogaology/recipe/{amber,berry,lime,azure}_guogao.json`（合成原料）
  - `data/guogaology/advancement/recipes/{amber,berry,lime,azure}_guogao.json`（配方解锁条件）
- `guogaology:fruit_cake_gel` = 果糕凝胶（`ModItems` 里 `FRUIT_CAKE_GEL=simple("fruit_cake_gel")`，中英语言键齐全）。
- 替换后全仓再无 `slime_ball` 残留；jar 内配方实测 `["minecraft:apple","minecraft:sugar","guogaology:fruit_cake_gel"]` ✔

## 四、QA 助手期望值同步（`ports/qa26/.../BoundaryChecks.java`）

它自 0.5.3.9 起就已过期（当时「所有果糕换成软糖罐」后不再有花面果糕兜底）：

- `tableGummy` 概率检查：`plain>7850&&plain<8150` → **`plain==10000`**（一律软糖罐）。
- 400 次试放的检查：原断言 `emittedFace>15 && mixed>0` 已不可能成立 ⇒ 改为
  **`emittedFace==0 && mixed==0`**，并新增**每块桌板概率 ≈1%** 的统计断言（实测落在 0.4%~2% 区间）。
- 该文件属开发用 QA 源集，需 Gradle `:26.2:mergeQaJar` 才能编译运行 ⇒ **本轮未编译验证**。
